# Folder selection acceptance — 0.7.0

Use a disposable project and, for cloud checks, an account/project whose test resources can be changed. Keep copies of source files. This upgrade adds schema 007; older applications cannot safely open the upgraded registry.

1. Create supported documents at the root, `Drafts/Nested/notes.md`, and `Drafts-copy/keep.md`, plus an empty folder. Register the root and enable tracking. Expand the folder tree; nested and empty folders should be visible. Built-in ignored directories, symlinks/junctions and unsupported file types retain the discovery policy.
2. Uncheck Drafts. Its descendants should be disabled/excluded and its parents mixed. Before saving, verify existing history/cloud membership is unchanged. Discard should restore the saved checkboxes. Selecting a mixed parent should include all its descendants.
3. Edit the draft again and navigate to Settings or All projects. Verify Keep editing preserves it; Discard continues without saving; Save changes and continue saves before navigation. Repeat with the Windows window-close button. During an in-flight save, duplicate saves/discards must be disabled. A failed save must keep the window/project and draft available. A forced process termination is outside this close prompt.
4. Save Drafts excluded, close/reopen the app, and verify it remains unchecked. Edit notes and add a new supported document below Drafts, then refresh/reconcile. Neither should get a new captured version. `Drafts-copy/keep.md` must still track. Existing snapshot/history rows, source bytes, archives and saved chats must remain available.
5. Include Drafts and Save. Reconcile with tracking enabled: changed/new files should capture using the existing history where applicable. Tracking off must remain off. Repeat with an individual file, the project-root checkbox, and a missing excluded path restored later.
6. With disposable cloud data indexed, exclude a folder and Save. Verify affected index associations are removed, unrelated entries remain, and local snapshots/raw uploaded Files remain. New questions should wait for verified removal. Reinclude and sync using the saved selection/mode/store; independent document/version opt-outs must remain excluded.
7. Repeat exclusion while uploads are paused, and after removing/re-registering with explicitly retained cloud data and sync still off. Saved index removals may proceed, but uploads and cloud enablement must remain off/paused. With the original credential unavailable or a simulated removal failure, verify visible errors/retry, persistence after restart and successful explicit retry. No unrelated cloud resources should be removed.
8. Lose the project root while a selection draft exists. The draft must survive the folder-loss update; Save must refuse until the root is available/reassigned. Discard must permit navigation/close. Reassign to the same project at a different location and verify relative saved exclusions remain.
9. Open an existing schema-006 registry containing ignored initial files. Upgrade should preserve those exclusions and local history. A stale selection revision must fail visibly instead of overwriting newer saved choices. Reload/discard should recover the current selection.

Automated provider mocks and UI close-event mocks cover failure/race paths; the real Windows close flow, installed upgrade and authenticated provider behavior still require installed acceptance.
