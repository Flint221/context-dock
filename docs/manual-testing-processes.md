# Current processes — 0.6.2 manual checks

Use a disposable preview and save work before testing Stop. Do not bulk-stop unfamiliar apps. Nothing here requires enabling document tracking or cloud access.

1. Install the 0.6.2 build, preserving the existing application identifier/data. Open **Current processes** directly above Settings. It must work with no registered projects and with projects awaiting folder reassignment. Add project should not appear on this page. Check light/dark themes and narrow-window horizontal table scrolling.
2. Start a disposable local website preview using your usual development tool. Note its port and PID. Refresh the list and search that port. Check executable path, PID, parent, start time and all endpoints. Compare counts with Windows Resource Monitor if desired. IPv4/IPv6 wildcard bindings are separate endpoints, not separate apps. A UDP binding does not imply a listening TCP website.
3. Click **Preview** for its loopback/wildcard TCP endpoint. Your default browser should open the exact local port. If the server uses HTTPS, check **Use HTTPS for previews** and try again; uncheck to restore HTTP. Nonweb protocols may fail in the browser. UDP and LAN-only endpoints should have no Preview. Copy endpoint and Details and inspect the clipboard.
4. Toggle TCP/UDP and Loopback + wildcard filters both ways. Search by name, PID and path. Clear the search. Switch **Show** to **User apps and listeners**: eligible apps without ports should appear; switch back to hide them. Selection should clear when filters change so hidden items are not accidentally stopped.
5. Select the disposable preview, then uncheck it. **Stop selected** must return to zero and stay disabled after refresh. Select it again, choose Stop selected and Cancel. The preview must remain running. Individual Stop must show the same whole-process warning, exact path/PID and all known endpoints.
6. Confirm Stop for the disposable preview only. Expect a confirmed result for that PID; refresh should remove the owner if it exited and the port should become unavailable. This force stops the owning process, not just the selected endpoint. If a parent relaunches it, the new PID/creation time should be a new row and should not inherit selection. Windows refusal or delayed exit must show an error/unconfirmed result.
7. Optionally start two disposable previews. Filter to their names/ports; confirm that **Stop all shown** lists exactly those intended eligible processes across all pages. Cancel if anything unfamiliar appears. Confirm only this disposable target list, then inspect each result. Windows/system/service entries and ContextDock-related processes must be disabled/excluded.
8. Enable **Refresh every 5 seconds** and start/stop a disposable preview separately. The list should catch up. Uncheck the option and verify updates now require Refresh. Re-enable, navigate to Settings, then return: polling should reset to off. Hiding the application page or opening a stop review pauses polling; it must never trigger automatic stop actions.
9. Click **Inspect startup entries**. Check names/source locations against Windows where available. The list says entries may be disabled and does not attribute them to a process. **Windows Startup apps** should open Windows Settings. No startup entry, scheduled task, service or restart preference should be modified. Stop does not prevent relaunch after reboot; manage an identified entry in Windows or the owning app.
10. Close/reopen ContextDock. Navigation and project history/cloud settings should be unchanged; process inventory is freshly read on opening the tab. HTTPS, selection and auto-refresh reset. Browser launch, Startup Settings launch, installation/upgrade, visual layout and reboot behavior require these interactive checks; automated tests alone do not establish them.

The native automated integration test binds disposable IPv4/IPv6 TCP/UDP sockets, refuses self-stop, checks stale creation identity, and terminates only its own temporary child fixture. It never stops a pre-existing user process or changes startup configuration. Frontend tests use mocked native services.
