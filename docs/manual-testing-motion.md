# Motion and action feedback — 0.6.3

Use disposable projects and previews. Animation and progress must never submit an action, bypass confirmation, delay native work or change cloud/tracking consent.

1. Navigate Dashboard → Projects → Current processes → Settings and back. Page headings and sections should arrive in order with short, gentle movement; content and controls should be usable immediately. Scroll down a long page, then switch pages: the destination should start at the top. Ordinary background status updates must not replay entry or jump the scroll position.
2. Hover/press project cards, navigation, primary actions, ordinary buttons and destructive buttons. Cards lift gently, arrows/icons respond, and mouse press gives a small tactile response. Hovering must never trigger a native action. Disabled buttons stay disabled and do not move. Keyboard Tab focus should remain conspicuous without requiring hover. Enter/Space activation must still work.
3. Open Add project, Rename or a non-destructive review. The dialog and backdrop should enter smoothly; Escape/Cancel and close must retain their existing guards. Focus should return to the prior control when it still exists. Confirmations should remain reachable in narrow windows and long dialogs. Do not confirm any destructive action merely to test animation.
4. Refresh a disposable project, register a disposable folder, check a reassignment destination, or compare versions. Unknown-duration work should have an animated progress track without a fabricated percentage. A successful action can show full confirmed progress; a failure must show its error without claiming completion. Retrying and cancellation retain their existing behavior. Paid/cloud actions still require their normal explicit authorization.
5. On an explicitly opted-in cloud project, observe the **Indexed versions** meter. Its numerator should match backend indexed versions and its denominator indexed + pending + failed/uncertain counts. It should change with status events, without elapsed-time estimates. Failed/uncertain captures remain outside the indexed fraction. Paused status must remain explicit. Current-version/source/selection readiness can continue blocking questions even when the known index count is full. Turning cloud off or losing verified status must hide this meter; it must never restart uploads by itself.
6. While typing a document/process filter or editing a draft, allow a metadata/cloud refresh. The draft, focus and component state should persist. Navigate to another page and back: a new page should receive its entry transition normally. Enable process auto-refresh, then watch several cycles: the list should update without a loading panel repeatedly pushing it down. Explicit Refresh processes should still show progress. Turn auto-refresh off and verify no new polls are scheduled.
7. Check light/dark/system themes at 1180px width and the 780px minimum. Primary actions should stay visible, action groups wrap, long paths remain readable and wide process tables scroll inside their panel. Summary numbers should align when labels wrap. Regular buttons should have at least 40px targets; deliberately compact process actions are at least 34px and modal close 36px.
8. Turn off animation using the OS accessibility preference, then return to ContextDock. Page/card/dialog entry, spinner/progress travel and hover/press movement should stop. Progress must remain visible (static stripes for unknown duration, measured fill for real counts), focus must remain visible, and every control should still work. Restore the OS setting afterward if desired; the app should respond without a stored preference reset.

Automated frontend tests cover progress semantics, finite bounds, confirmed completion/idle, live indexed/failure/paused/off counts, and route-only reset with preserved input. Browser review uses a generated build-only fixture with synthetic data and replaced native services. Its 780px iframe and forced reduced-motion stylesheet verify responsive/motion rules without touching user data or OS preferences. This does not establish installed WebView2 performance, actual cloud timing or interactive upgrade behavior.
