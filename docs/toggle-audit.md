# Toggle and reversal audit — ContextDock 0.6.2

## Numbered initialization addition — 0.7.2

Initial source choices remain draft until Capture selected and enable. Selected clear numeric exports are imported in order within one same-directory/type family; unchecked sources retain file exclusions. Initial import never moves sources. Repeated/restarted work is journaled and hash-idempotent. Re-adding/resuming a legacy project only repairs unchanged simple initial histories after cloud resources are gone; original history IDs/snapshots remain accessible, and cloud family choices for repaired groups require explicit re-selection. Ambiguous, changed or retained-cloud cases explain why they remain separate. See [numbered-import acceptance](manual-testing-numbered-import.md).

## Folder-selection addition — 0.7.0

Folder/file tree checkboxes are drafts until Save. Discard restores the saved selection; guarded navigation/close offers Save, Discard or Keep editing, and failed saves retain the draft. Saved folder rules persist and exclude present/future descendants from capture and cloud indexing, while retaining source files, snapshots, archives and history. Reinclude restores path eligibility under existing tracking/cloud settings, saved version policy and independent cloud opt-outs. Scoped index removals can finish with uploads paused or explicitly retained data off; failed removals remain retryable and questions wait for verification. Regression details and installed acceptance are recorded in [verification](verification.md) and [the walkthrough](manual-testing-folder-selection.md).

October 20, 2026. Scope: application control handlers, native state transitions, request authorization, persistence, failure readback and focused regressions on `milestone-6`. Automated cloud evidence uses a scripted provider and temporary SQLite/source/snapshot stores. Installed live-account behavior remains user acceptance; no real credentials or user cloud resources were inspected or changed.

Individual **Remove association** / **Delete uploaded File** actions in the advanced index view have their own explicit per-version exclusion and deletion confirmations. A family checkbox does not silently revoke an earlier individual-version exclusion. Turning whole-project Cloud sync off cleans the owned cloud resources; subsequent enablement builds a fresh index from the saved selection and policy. Reassignment, stopping tracking/archival, and removing a local chat do not purge local snapshots or restore old source bytes into working files.

## Gaps corrected in this audit

- Family opt-outs previously waited behind unrelated uploads/current-version readiness and remained queued while paused. Saved removal intents now have a separate priority path and narrow GET/DELETE authorization without resuming uploads.
- Association deletion previously marked a job removed without verifying its receipt or remote absence. Failures now remain visible and retryable across restart.
- A lost upload receipt followed by deselect/reselect could lose its recovery state and allow another upload. Recovery-phase jobs now reconcile the existing File by identity and hash.
- Re-enabling with an empty or ineligible saved selection could choose all other eligible families. Saved selections are now honored, with an explicit review error when they cannot be restored.
- Cloud-view pause/key decoration could hide cleanup failure status. Pending/failed cleanup and failed document removal now remain visible.
- A paused project previously displayed an unchecked main Cloud sync switch despite retaining enabled cloud resources. The switch now reflects saved enablement; the label states Paused, and unchecking consistently opens verified deletion.
- A late document-removal result could overwrite the stop intent saved by a concurrent whole-project Off. Revision checks now preserve that cleanup state while it waits for the HTTP gate.
- Opt-out confirmation copy now distinguishes saved settings, verified index removal, retained uploads, whole-project erasure and paused uploads.

## Installed acceptance with disposable content

1. Use two independently tracked disposable families and two captures in one family. In your own test account, enable Cloud sync and select Full captured history. Verify the three version/File mappings and this project's store ID.
2. Uncheck one family, then Cancel. Its checkbox, index entries and mappings must remain unchanged. Uncheck again, review and confirm. All its captures must leave this store while the other family stays indexed; removal progress/failure must remain visible until remote absence is verified.
3. Select the family again and confirm. The same store should regain the captures allowed by the policy, reusing retained upload IDs. Repeat Full history→Current only→Full history and check for extra identical uploads.
4. Pause uploads. Deselect a family and confirm: removal must complete while uploads remain paused. Restore the family: uploads/re-attachment must wait for explicit resume. Turn automatic sync off/on with cancellation once on each change and verify saved flags.
5. With paused uploads, make a selected source temporarily unavailable or disconnect the tested key. A pure deselection can still be saved. Actual deletion must wait for the tested original key and remain pending/retryable, without enabling uploads. Restore access/key, use Retry document removals and verify deletion.
6. Interrupt connectivity during removal, close/reopen the app, then retry. An unverified deletion must not be reported complete, lose its IDs, permit new questions or automatically resume uploads. A re-selected family must not be blindly uploaded again after an uncertain old upload.
7. Turn Cloud sync off, Cancel first, then confirm. Verify all stores/uploads owned by this installation/project are removed, including an old owned store if present. Other projects' stores remain intact. Re-enable and verify the saved subset/policy is restored into a fresh owned store. An empty or ineligible saved selection must ask for review.
8. Exercise local tracking and archival off/on using disposable sources, cancelling once before confirming. Old history/archives remain, tracking catches up once resumed, and archival never overwrites a conflict. The [Milestone 6 folder guide](manual-testing-milestone-6.md) covers missing-root recovery.

Keep keys out of chat, logs and this repository. These steps are live user acceptance; local mocked tests establish code behavior and request boundaries without operating on the user's account.
